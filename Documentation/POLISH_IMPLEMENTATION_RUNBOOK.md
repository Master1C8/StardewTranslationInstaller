# Технический runbook польского пакета Stardew Valley

Этот документ фиксирует практические знания, полученные при доводке польского пакета VN Revival до версии 1.0.4. Он дополняет [`TRANSLATION_GUIDE.md`](TRANSLATION_GUIDE.md): руководство по переводу отвечает за редактуру текста и глоссарий, а этот runbook — за Content Patcher, графику, XNB-шрифты, сборку, установку и проверку в игре.

## 1. Проверенный снимок пакета 1.0.4

На момент выпуска 1.0.4:

- внутренний код языка — `pl-vnrevival`;
- ID дополнительного языка — `VNRevival.StardewValleyPolish_Polish`, поскольку запись создаётся как `{{ModId}}_Polish`;
- Content Patcher UniqueID — `VNRevival.StardewValleyPolish`;
- установленная папка — `[CP] VN Revival Polish`;
- перевод разложен по 151 вторичному JSON-файлу;
- корневой `content.json` содержит 151 соответствующий `Include`;
- суммарно в переводных `Entries` находится 14 720 записей;
- `SpriteFont1` и `SmallFont` содержат по 282 глифа после расширения;
- Swift-набор содержит 6 тестов.

Количество файлов и записей — снимок версии, а не вечная константа. При добавлении текста обновлять этот раздел только после полного аудита `Include` и подсчёта уникальных записей.

## 2. Источник истины и поток установки

Источник истины находится в репозитории:

```text
Sources/StardewTranslationInstaller/Resources/ModPayload/
```

Установленная копия в `Stardew Valley/Contents/MacOS/Mods` — только результат сборки. Не исправлять её как основную: следующая установка перезапишет изменения.

Поток данных:

```text
исходный ModPayload
  → Swift resource bundle
  → Stardew Translation Installer.app
  → [CP] VN Revival Polish в Mods
  → Content Patcher
  → locale pl-vnrevival
```

После каждого изменения ресурса проверять не только исходник, но и три фактические копии:

1. файл в `Sources/.../ModPayload`;
2. файл внутри собранного `.app`;
3. файл внутри установленной папки мода.

Хеши критичных бинарных ресурсов должны совпадать между всеми тремя копиями.

## 3. Жёсткие правила Content Patcher

### 3.1. `Format` разрешён только в корне

Корневой `content.json` обязан содержать:

```json
{
  "Format": "2.9.0",
  "Changes": []
}
```

Файл, подключаемый через `Include`, обязан начинаться непосредственно с `Changes`:

```json
{
  "Changes": [
    {
      "Action": "EditData",
      "Target": "Strings/UI",
      "When": {
        "Language": "pl-vnrevival"
      },
      "Entries": {
        "AcceptQuest": "Przyjmij zadanie"
      }
    }
  ]
}
```

Нельзя помещать `Format` во вторичный файл. Content Patcher 2.9 отклоняет такой файл целиком. Эта ошибка раньше присутствовала во всех 152 вторичных файлах и визуально маскировалась тем, что сам язык и кнопка продолжали регистрироваться.

### 3.2. Пустые включения запрещены

Не оставлять файл с пустым `Changes` и не подключать его через `Include`. Удалить одновременно:

- сам пустой файл;
- соответствующий объект `Include` в корневом `content.json`.

### 3.3. Каждый переводной патч изолирован локалью

Каждый `EditData` обязан иметь:

```json
"When": {
  "Language": "pl-vnrevival"
}
```

Исключение — инфраструктурные загрузки, где используется `TargetLocale`, например шрифты и `TitleButtons`.

### 3.4. Аудит структуры

Перед выпуском проверить:

- все JSON разбираются;
- каждый `Include` ведёт в существующий файл;
- каждый вторичный файл подключён ровно один раз;
- нет дубликатов путей;
- нет вторичных `Format`;
- нет пустых `Changes`;
- в `Entries` нет дублирующихся ключей внутри одного target;
- все переводные `EditData` используют точный код `pl-vnrevival`;
- структура event-команд совпадает с английским оригиналом.

Успешный разбор JSON не доказывает, что Content Patcher принял патчи. Окончательная проверка всегда выполняется по `SMAPI-latest.txt`.

## 4. Кнопка языка

Кнопка `POLSKI VN` — PNG размером 174×78. Это не одна высокая кнопка, а два кадра по 174×39:

```text
y = 0…38   обычное состояние
y = 39…77  наведение/выбор
```

Подключение:

```json
{
  "Action": "Load",
  "Target": "Mods/{{ModId}}/Button",
  "FromFile": "assets/button.png"
}
```

Практические правила:

- размеры сами по себе недостаточны: фон, внутренняя рамка, базовая линия и высота букв должны совпадать с русской кнопкой VN Revival;
- разные версии официального `LanguageButtons` имеют различающиеся фон и палитру, даже при одинаковых размерах;
- для польской версии 1.0.3 фон и геометрия взяты непосредственно с русской кнопки, а текст заменён детерминированно;
- `VN` должен быть того же визуального размера, что и `POLSKI`, а не маленьким верхним индексом;
- нельзя масштабировать PNG с интерполяцией; только nearest-neighbour и целочисленная пиксельная сетка;
- проверять оба кадра, а не только верхнюю половину.

Файл `assets/button-polish.png` может сохраняться как рабочий дубль, но `content.json` загружает канонический `assets/button.png`.

## 5. Титульный интерфейс

Базовый титульный атлас хранится в:

```text
assets/title/TitleButtons.png
```

Точный размер — 400×655. Подключение обязательно ограничено польской локалью:

```json
{
  "Action": "Load",
  "Target": "Minigames/TitleButtons",
  "TargetLocale": "pl-vnrevival",
  "FromFile": "assets/title/TitleButtons.png"
}
```

Штатные рамки и иконки четырёх крупных кнопок остаются в базовом атласе. Общий
SMAPI-мод добавляет поверх них только надписи высокого разрешения из файла:

```text
LanguageSwitcherPayload/title-overlays/TitleLabels-polish.png
```

Размер файла — 888×174: четыре прозрачные ячейки по 222×174. Базовый
`TitleButtons*.png` содержит чистые штатные рамки и иконки без низкоразрешённых
надписей. Мод рисует каждую прозрачную ячейку от центра соответствующего
`ClickableTextureComponent` и применяет отношение `scale / baseScale`, поэтому
надпись совпадает с рамкой как в обычном состоянии, так и при hover-анимации.
Обычный и hover-цвета берутся из штатной палитры титульного меню.

Канонические подписи, согласованные с глоссарием:

| Английский | Польский |
|---|---|
| New | Nowa gra |
| Load | Wczytaj |
| Co-op | Kooperacja |
| Exit | Wyjdź |
| Back | Wstecz |
| Created by | Stworzone przez |

Правила подготовки:

- хранить утверждённый общий лист масок в `Scripts/assets/title-button-labels.png`;
- порядок 19 рядов должен совпадать с `languageCodes` в `PackageConfig.json`;
- только разрезать лист на прозрачные строки; не масштабировать и не фильтровать;
- базовый `TitleButtons*.png` сохранять размером 400×655 и очищать в нём только низкоразрешённые надписи, не меняя рамки и иконки;
- после сборки проверить, что папка оверлеев и DLL побайтово совпадают между исходником, приложением и установленным модом.

Генеративное изображение может использоваться только после явного утверждения
владельцем как полностью готовый входной файл. После утверждения код не должен
извлекать из него маски или заново собирать фон: он только вырезает заданные
прямоугольники и выводит их 1:1.

Красные крапинки на деревянных табличках присутствуют и в оригинальном русском атласе. Это часть текстуры дерева, а не повреждённые глифы. Случайные пиксели, связанные непосредственно с буквенной маской, напротив, нужно удалять.

## 6. Почему стандартного латинского шрифта недостаточно

`UseLatinFont: true` означает выбор латинского пути рендеринга, но не гарантирует наличие всех символов языка.

В базовых шрифтах Stardew Valley 1.6.15:

- `SpriteFont1.xnb` — 266 символов;
- `SmallFont.xnb` — 266 символов;
- из полного польского набора присутствуют только `Ó` и `ó`;
- отсутствуют `ĄĆĘŁŃŚŹŻąćęłńśźż`.

При отсутствии символа игра использует `defaultCharacter` (`*`) или некорректный резервный рисунок. Поэтому строка остаётся читаемой частично, а отдельные польские буквы выглядят «подглючившими». Проверка только ASCII-строк эту проблему не обнаруживает.

Польский пакет загружает два локализованных шрифта:

```json
{
  "Action": "Load",
  "Target": "Fonts/SpriteFont1",
  "TargetLocale": "pl-vnrevival",
  "FromFile": "assets/fonts/SpriteFont1.xnb"
},
{
  "Action": "Load",
  "Target": "Fonts/SmallFont",
  "TargetLocale": "pl-vnrevival",
  "FromFile": "assets/fonts/SmallFont.xnb"
}
```

После расширения каждый шрифт содержит 282 символа: 266 исходных плюс 16 отсутствовавших польских глифов. `Ó/ó` повторно не добавляются.

## 7. Устройство и расширение XNB SpriteFont

После распаковки `SpriteFont1.xnb` или `SmallFont.xnb` через xnbcli получаются PNG и JSON. В `content` находятся четыре параллельных списка:

- `glyphs` — координаты прямоугольников в PNG-атласе;
- `cropping` — расположение глифа относительно строки;
- `characterMap` — Unicode-символы;
- `kerning` — левый отступ, ширина и правый отступ.

Для каждого индекса элементы всех четырёх списков относятся к одному символу. Их длины всегда должны совпадать.

### 7.1. Как построены польские символы

- `ĆŃŚŹ` и строчные варианты: базовая буква плюс acute, снятый с существующих `Á/á`;
- `Ż/ż`: базовая `Z/z` плюс пиксельная точка;
- `ĄĘ` и строчные варианты: базовая буква плюс нижний хвост, построенный по геометрии `Ç/ç`;
- `Ł/ł`: базовая `L/l` плюс диагональный штрих;
- `Ó/ó`: используются исходные игровые глифы.

Все операции выполняются без сглаживания.

### 7.2. Критический инвариант MonoGame

`characterMap` обязан быть строго отсортирован по Unicode. Недостаточно добавить новые символы в конец списка. MonoGame отклонит весь `SpriteFont` с ошибкой:

```text
Invalid SpriteFont. Character map must be in ascending order.
```

После добавления символов нужно совместно отсортировать кортежи:

```text
(characterMap[i], glyphs[i], cropping[i], kerning[i])
```

Нельзя сортировать только `characterMap`: это привяжет символы к чужим рисункам и метрикам.

### 7.3. Обязательная проверка XNB

После упаковки:

1. распаковать получившийся XNB обратно;
2. проверить одинаковые длины четырёх списков;
3. проверить строгий Unicode-порядок `characterMap`;
4. проверить наличие всего набора `ĄĆĘŁŃÓŚŹŻąćęłńóśźż`;
5. визуально посмотреть новый участок PNG-атласа;
6. запустить игру и проверить журнал SMAPI.

Одинаковый размер файла и успешная команда `xnbcli pack` не доказывают, что MonoGame примет шрифт.

В среде без интернета xnbcli может сообщить, что не смог проверить собственное обновление через GitHub. Это не ошибка локальной распаковки или упаковки: оценивать результат нужно по созданному файлу, round-trip и последующему запуску SMAPI.

## 8. Сборка без устаревших ресурсов

Обычный `cp -R` сливает каталог нового `.app` со старым. Удалённый из исходников файл может сохраниться внутри предыдущей сборки и снова попасть в установщик.

`Scripts/build-app.sh` перед сборкой обязан удалить только генерируемый каталог:

```text
dist/Stardew Translation Installer.app
```

и затем создать приложение заново. Не удалять весь проект или произвольную папку `dist`.

Для Swift использовать полный Xcode toolchain, а не случайно выбранные Command Line Tools. Проверенная команда тестов:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
CLANG_MODULE_CACHE_PATH=/private/tmp/stardew-swift-module-cache \
swift test --disable-sandbox
```

Без явного `DEVELOPER_DIR` возможна несовместимость версии компилятора и SDK. В ограниченной среде SwiftPM также может попытаться записать module cache вне разрешённой папки; отдельный путь в `/private/tmp` делает запуск воспроизводимым.

При синхронизации проекта на рабочий стол простой `rsync -a` тоже не удаляет устаревшие файлы. Если файл был удалён из исходников, отдельно проверить его отсутствие в:

- рабочем репозитории;
- собранном приложении;
- копии проекта на рабочем столе;
- установленном моде;
- финальном ZIP.

## 9. Безопасный перезапуск игры

Content Patcher кэширует загруженные изображения и шрифты. Замена PNG/XNB во время работы не обновляет уже открытый экран: нужен полный перезапуск игры.

Перед закрытием:

1. проверить `SMAPI-latest.txt`;
2. убедиться, что игра остаётся в `titleScreenGameMode`, либо получить подтверждение пользователя, что прогресс сохранён;
3. предпочесть штатный `Command-Q` или обычный выход;
4. не завершать процесс принудительно при возможном несохранённом прогрессе.

Файл `~/.config/StardewValley/startup_preferences` хранит активный дополнительный язык. Для польского ожидается:

```xml
<languageCode>VNRevival.StardewValleyPolish_Polish</languageCode>
```

Не редактировать этот файл во время работы игры: при выходе игра может перезаписать настройку старым значением.

## 10. Что должно появиться в журнале SMAPI

Успешный запуск 1.0.4 содержит строки по смыслу:

```text
Stardew Valley — Polish by VN Revival 1.0.4
Content Patcher loaded asset 'Fonts/SpriteFont1.pl-vnrevival'
Content Patcher loaded asset 'Fonts/SmallFont.pl-vnrevival'
Content Patcher loaded asset 'Minigames/TitleButtons.pl-vnrevival'
Context: locale set to mod (pl-vnrevival)
Full-resolution title buttons enabled for pl-vnrevival; button bounds: 222x174, 222x174, 222x174, 222x174
```

Не должно быть:

```text
Error loading patch
Can't apply patch
incorrectly set asset to a null value
Invalid SpriteFont
root-only field
```

Строка `loaded asset` после предшествующей ошибки не всегда означает успех: Content Patcher может записать попытку загрузки, а затем сообщить, что замена заблокирована. Проверять весь соседний блок журнала, а не искать одно положительное совпадение.

## 11. Визуальная матрица проверки

Минимум проверить в игре:

1. экран выбора языка — обычное и hover-состояния `POLSKI VN`;
2. главное меню — `Nowa gra`, `Wczytaj`, `Kooperacja`, `Wyjdź`, `Wstecz`; надписи четырёх крупных кнопок остаются внутри штатных рамок и синхронно масштабируются при hover;
3. создание персонажа — красный и обычный UI-шрифты;
4. инвентарь/статистика — строки с диакритикой;
5. диалог и системное сообщение;
6. малый шрифт в подсказках и компактных подписях.

Контрольная строка для всех символов:

```text
ĄĆĘŁŃÓŚŹŻ ąćęłńóśźż
```

В версии 1.0.4 визуально подтверждены, в частности:

- `ś` в `Obecne środki`;
- `Ł` и `ą` в `Łączne zarobki`;
- `ń` в `Dzień`.

## 12. Глоссарий и редакторский контроль

Технически загруженная строка всё ещё может быть неправильным переводом. Канонический источник терминов — польский слой общего глоссария VN Revival в `Documentation/glossary/glossary.pl.json` и соответствующая каноническая запись SiteForMods.

Для титульного интерфейса зафиксированы `Nowa gra`, `Wczytaj`, `Kooperacja`, `Wyjdź`, `Wstecz`. Не менять эти основы ради более короткого или буквального варианта без обновления глоссария.

Исходный черновик, включая ранее созданный через LUNA перевод, считается только кандидатом. Перед выпуском каждая строка должна пройти:

1. сверку с английским XNB поддерживаемой версии;
2. проверку плейсхолдеров и команд;
3. проверку терминов по стабильным ID глоссария;
4. редактуру естественного польского;
5. повторный полный проход после любых исправлений.

Черновой машинный перевод может снизить стоимость первичного заполнения, но не заменяет финальную проверку: основные дефекты этого пакета были обнаружены именно на этапах структурного, терминологического и игрового аудита.

## 13. Финальный выпускной gate

Пакет нельзя считать готовым, пока не выполнены все пункты:

- все JSON валидны;
- вторичные файлы не содержат `Format`;
- нет пустых или неподключённых файлов;
- количество файлов, `Include` и уникальных путей совпадает;
- глоссарные термины применены последовательно;
- плейсхолдеры и event-структуры совпадают с английским источником;
- кнопка имеет размер 174×78 и два кадра;
- `TitleButtons.png` имеет размер 400×655 и локализован через `TargetLocale`;
- `TitleLabels-polish.png` в payload переключателя имеет размер 888×174, содержит только прозрачные маски надписей и центрируется по штатным кнопкам;
- оба XNB-шрифта проходят round-trip и содержат полный польский набор;
- `characterMap` обоих шрифтов отсортирован;
- `swift test --disable-sandbox` проходит;
- `Scripts/build-app.sh` создаёт приложение с чистого каталога;
- подпись `.app` проверяется через `codesign --verify --deep --strict`;
- финальный ZIP проходит `unzip -t`;
- установленная версия и ресурсы совпадают с исходниками по хешам;
- новый запуск SMAPI не содержит ошибок польского content pack;
- визуально проверены оба интерфейсных шрифта, титульный атлас и кнопка языка.

Только сочетание структурных тестов, журнала SMAPI и визуальной проверки доказывает, что локализация действительно работает.
