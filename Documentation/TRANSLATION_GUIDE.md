# Руководство по переводу Stardew Valley

Этот документ предназначен для модели или переводчика, продолжающего любой перевод **VN Revival**. Цель проекта — добавлять в Stardew Valley отдельные языки `*-vnrevival` через Content Patcher, не заменяя оригинальные XNB-файлы игры.

Текущая сборка — единый установщик 19 завершённых языков VN Revival. Точный канонический список кодов хранится в `PackageConfig.json`. Пользователь получает простой сценарий: открыть → дождаться установки всех переводов → нажать кнопку запуска. Нужный язык выбирается уже внутри Stardew Valley; отдельный выбор в установщике не нужен.

## 0. Универсальный контракт языкового пакета

Язык сборки задаёт файл:

```text
Sources/StardewTranslationInstaller/Resources/PackageConfig.json
```

Он содержит:

- `siteLocale` — точный код языка SiteForMods;
- `languageCodes` — список уникальных внутренних кодов дополнительных языков Stardew Valley;
- `nativeLanguageName` — название языка на нём самом;
- `uniqueID` — Content Patcher UniqueID конкретного пакета;
- `modFolderName` — безопасное имя папки в `Mods`;
- `steamAppID` — приложение, запускаемое после установки;
- `copy` — весь видимый текст установщика на языке сборки.

Установщик принимает единый канонический каталог из 30 языков SiteForMods:

```text
zh en ru es pt-BR ja de ko fr tr pl zh-TW it th vi id uk ar cs hu nl fa ro hi
fil el bg sr sw he
```

Список синхронизирован с `SITE_LOCALE_CODES` в `SiteForMods/lib/language-data/site-locales.ts`. При изменении списка сайта нужно вместе обновить `TranslationPackage.supportedSiteLocales` и тесты.

`PackageConfig.json`, `ModPayload/manifest.json` и `ModPayload/content.json` обязаны совпадать:

- `uniqueID` конфигурации равен `UniqueID` манифеста;
- `languageCode` конфигурации равен `LanguageCode` в `Data/AdditionalLanguages`;
- все переводные `EditData` используют этот же код в `When.Language`;
- `modFolderName` уникален для единого пакета переводов.

Установщик проверяет общий `UniqueID` и наличие каждого кода из `languageCodes` перед копированием. Для нового языка нужно добавить согласованную запись в конфигурацию, локализованные Content Patcher-файлы и кнопку языка, затем заново сгенерировать корневой `content.json` и собрать приложение.

Настройки шрифта находятся в `ModPayload/content.json` и зависят от письменности. Для латиницы можно использовать совместимый латинский шрифт игры; для кириллицы, CJK, арабского, индийских и других письменностей нужно выбрать или приложить совместимый игровой шрифт и проверить все нужные символы. Поддержка пакета установщиком не гарантирует, что движок Stardew Valley корректно выполнит shaping, bidi/RTL или переносы конкретной письменности: такие языки требуют проверки в игре.

## 1. Что является переводом

Установщик написан на Swift, но игровые тексты находятся не в Swift-коде. Перевод хранится в Content Patcher JSON-файлах:

```text
Sources/StardewTranslationInstaller/Resources/ModPayload/
├── manifest.json
├── content.json
└── assets/
    └── translations/
        ├── polish/
            ├── ui.json
            └── …
        └── <other-language>/
            └── …
```

`content.json` регистрирует каждый код из `PackageConfig.json`, загружает соответствующие кнопки и шрифты и явно подключает каждый файл перевода через `Include`. Патчи разнесены по языковым каталогам в `assets/translations/`.

Во время сборки каталог `ModPayload` помещается внутрь приложения. Во время установки он атомарно копируется в:

```text
Stardew Valley/Contents/MacOS/Mods/[CP] VN Revival Languages/
```

Исходники в этом репозитории — источник истины для мода. Никогда не редактировать установленную копию как основную: следующая установка её перезапишет.

## 2. Обязательный единый глоссарий

Глоссарий — обязательный словарь терминологических решений. Он един для всей игры и всех языковых проектов SiteForMods. Английская запись принадлежит Stardew Valley, а внутри неё хранятся отдельные переводы для локалей проектов. В этом репозитории приложены английский снимок и все канонические редакторские слои Stardew Valley. Сборка использует слой, соответствующий её точному `siteLocale`.

Каждая английская запись содержит стабильный `id`, `priority`, `term`, пояснение `meaning`, категорию и необязательную точную ссылку на источник. Каждый переводной слой сопоставляет тот же `id` с полями `term` и `meaning`. Стабильные ID нельзя менять после появления переводов.

В репозитории сохранены рабочие снимки для активных и незавершённых пакетов:

```text
Documentation/glossary/glossary.en.json
Documentation/glossary/glossary.ru.json
Documentation/glossary/glossary.pl.json
Documentation/glossary/glossary.ar.json
Documentation/glossary/glossary.zh-TW.json
Documentation/glossary/glossary.th.json
Documentation/glossary/glossary.vi.json
Documentation/glossary/glossary.id.json
Documentation/glossary/glossary.fa.json
Documentation/glossary/glossary.hi.json
Documentation/glossary/glossary.sw.json
```

В английском снимке 673 записи, и каждый переводной снимок содержит ровно 673 соответствия внутри объекта своей локали. У термина без подходящей конкретной страницы `sourceUrl` намеренно отсутствует; общую статью нельзя подставлять вместо точного источника.

Канонические редактируемые файлы находятся в репозитории SiteForMods:

```text
data/games/stardew-valley/glossary.json
data/games/stardew-valley/glossary-translations.json
```

После редакторских изменений обновить английский снимок и каждый изменённый переводной снимок из этих файлов. Публикация глоссария — отдельная контентная операция, для неё не нужен деплой сайта. После явного разрешения владельца в доверенной среде SiteForMods выполнить `npm run glossary:check`, затем направить `DATABASE_URL` на нужную CMS и запустить `npm run glossary:sync`. Общий CLI атомарно синхронизирует все канонические игры и локали, сохраняет отсутствующие в каноническом файле переводы и выводит ожидаемые количества записей и локалей. Запуск приложения с новым fingerprint остаётся страховочной сверкой, а не штатным способом публикации глоссария. `scripts/sync-stardew-glossary.ts` — только исторический recovery-инструмент, не обычный publisher. Полный контракт находится в `SiteForMods/docs/GLOSSARY-WORKFLOW.md`.

Если содержимое различается, не смешивать версии вручную: сначала проверить число записей, набор стабильных ID и выяснить, был ли после последнего изменения выполнен CMS-sync. Сверить канонические файлы и снимки можно так:

```sh
cmp Documentation/glossary/glossary.en.json \
  /Users/antonkrutov/Desktop/SiteForMods/data/games/stardew-valley/glossary.json
for locale in ru pl ar zh-TW th vi id fa hi sw; do
  jq --arg locale "$locale" '{($locale): .[$locale]}' \
    /Users/antonkrutov/Desktop/SiteForMods/data/games/stardew-valley/glossary-translations.json \
    > "/tmp/glossary.$locale.json"
  cmp "Documentation/glossary/glossary.$locale.json" "/tmp/glossary.$locale.json"
done
```

Текущий локальный снимок считать рабочим источником для установщика, только если он полностью совпадает с каноническими файлами SiteForMods. Наличие более поздней даты файла само по себе недостаточно.

Порядок работы с глоссарием:

1. Найти английский термин или его устойчивую фразу по `term`, затем проверить `meaning` и категорию.
2. Взять решение для `siteLocale` сборки из записи с тем же `id`.
3. Согласовать падеж, число и регистр с предложением, но не менять саму терминологическую основу.
4. Если в тексте появился важный повторяющийся термин, которого нет в глоссарии, сначала предложить новую английскую запись и переводы для всех канонических локалей. Не создавать дубликат под другим ID и не оставлять новый ID только в части слоёв.
5. Для источника указывать только конкретную страницу, действительно описывающую термин. Если точной страницы нет — ссылка не нужна.

Запрос «переведи глоссарий», «закончи локаль глоссария», «проверь/вычитай/проведи аудит глоссария» или «доведи глоссарий до готовности» без дополнительного ограничения всегда означает полный редакторский цикл, а не один переводческий или проверочный проход. Просьба о проверке по умолчанию включает исправление всех найденных объективных проблем и повтор обеих полных вычиток до прохождения критерия готовности. Только явное указание «только отчёт», «ничего не меняй» или равнозначный запрет превращает проверку в read-only; даже тогда без отдельно ограниченной выборки нужно проверить все записи.

1. Перевести все `term` и `meaning` напрямую с английского слоя и проверить точный набор и порядок ID.
2. Выполнить отдельную построчную сверку каждой записи с английским оригиналом на полноту условий, списков, исключений, различий и внутренних ссылок.
3. Выполнить ещё одну полную вычитку каждой записи как естественного текста целевого языка: грамматика, идиоматика, имена, регистр и единообразие терминов.
4. Исправить все найденные проблемы, снова запустить структурные проверки и начать обе полные вычитки заново.
5. Считать локаль редакторски готовой только после двух последовательных полных проверок всех записей без новых объективных замечаний. Любая последующая правка сбрасывает счётчик чистых проверок.

Автоматические проверки, поиск подозрительных строк, сравнение длины и выборочная проверка помогают находить кандидатов, но не заменяют построчную вычитку всего слоя. Успешный JSON, точные 673 ID и отсутствие пустых строк доказывают только структурную целостность. Если доступен независимый редактор или явно разрешённый субагент, одну из финальных проверок выполнять как холодное независимое ревью; автор всё равно обязан сам прочитать оригинал и закрыть каждое замечание.

Пример поиска одной пары по стабильному ID:

```sh
jq '.[] | select(.id == "community-center")' Documentation/glossary/glossary.en.json
jq '.ru["community-center"]' Documentation/glossary/glossary.ru.json
jq '.pl["community-center"]' Documentation/glossary/glossary.pl.json
```

Приоритеты помогают порядку ревью: `P0` — ключевые имена, интерфейс и базовые механики; `P1` — основной широкий словарь; `P2` — редкие или узкие термины. Приоритет не разрешает нарушать уже принятое написание.

## 3. Откуда брать английский оригинал

Переводить нужно по английским ассетам той версии игры, которую поддерживает мод, сейчас Stardew Valley 1.6.15. Не восстанавливать строки по памяти, вики или официальному русскому тексту.

### Готовый английский источник

На этой машине уже подготовлена распакованная английская выборка:

```text
~/Developer/data/stardew-english-unpacked/
```

Сейчас в ней 187 JSON-файлов из `Strings`, `Characters` и `Data`. Начинать нужно именно отсюда. Например:

```text
unpacked-all/Strings/UI.json
unpacked-all/Characters/Dialogue/Abigail.json
unpacked-all/Data/Events/Town.json
```

xnbcli оборачивает словарь ассета в верхнеуровневое поле `content`. Английские ключи и строки находятся внутри него:

```json
{
  "header": { "target": "w" },
  "content": {
    "AcceptQuest": "Accept Quest"
  }
}
```

Читать исходник можно через `jq`:

```sh
jq '.content.AcceptQuest' \
  "$HOME/Developer/data/stardew-english-unpacked/Strings/UI.json"

jq '.content | to_entries[0:20]' \
  "$HOME/Developer/data/stardew-english-unpacked/Characters/Dialogue/Abigail.json"
```

Путь относительно `unpacked-all` даёт Content Patcher target: `Strings/UI.json` превращается в `Strings/UI`, а `Characters/Dialogue/Abigail.json` — в `Characters/Dialogue/Abigail`. В мод переносится не весь xnbcli JSON и не поле `header`, а выбранные ключи из `content` в `Entries` патча.

### Если готовой распаковки нет или игра обновилась

Игра установлена в:

```text
/Users/antonkrutov/Library/Application Support/Steam/steamapps/common/Stardew Valley
```

Английские XNB находятся в:

```text
/Users/antonkrutov/Library/Application Support/Steam/steamapps/common/Stardew Valley/Contents/Resources/Content/
```

Базовый файл **без суффикса локали** — английский оригинал:

```text
Strings/UI.xnb                         ← английский
Strings/UI.ru-RU.xnb                   ← официальный русский, не источник перевода
Characters/Dialogue/Abigail.xnb       ← английский
Characters/Dialogue/Abigail.ru-RU.xnb ← официальный русский, не источник перевода
```

Не использовать `*.ru-RU.xnb` и другие файлы с языковым суффиксом как английский источник. Перед новой большой волной перевода сверить версию игры и заново извлечь базовые XNB, если Steam обновил игру.

Закреплённый локальный распаковщик находится здесь:

```text
~/Developer/tools/xnbcli/xnbcli
```

Это постоянная локальная копия инструмента, а не путь внутри временного задания
Codex. Она не входит в Git-репозиторий. Проверенный SHA-256 исполняемого файла:
`54fff99783dc1946b70214f81e2eff47774acf1829c395f3d9ef147462959aa3`.
Готовое английское извлечение для аудитов хранится отдельно в
`~/Developer/data/stardew-english-unpacked/` и также не публикуется в GitHub.

Безопасная схема извлечения:

1. Создать отдельный временный каталог вне папки игры с подпапками `packed` и `unpacked`.
2. Скопировать в `packed` нужные базовые `.xnb` без суффикса локали, сохранив структуру `Strings/...`, `Characters/...` или `Data/...`.
3. Запустить `xnbcli unpack <packed> <unpacked>`.
4. Читать полученные JSON из `<unpacked>`; оригинальную папку игры не изменять.

Пример для одного безопасно скопированного ассета:

```sh
SOURCE_ROOT=/private/tmp/stardew-english-source
GAME_CONTENT='/Users/antonkrutov/Library/Application Support/Steam/steamapps/common/Stardew Valley/Contents/Resources/Content'
XNBCLI="${XNBCLI:-$HOME/Developer/tools/xnbcli/xnbcli}"

mkdir -p "$SOURCE_ROOT/packed/Strings" "$SOURCE_ROOT/unpacked"
cp "$GAME_CONTENT/Strings/UI.xnb" "$SOURCE_ROOT/packed/Strings/UI.xnb"
"$XNBCLI" unpack "$SOURCE_ROOT/packed" "$SOURCE_ROOT/unpacked"
jq '.content | to_entries[0:20]' "$SOURCE_ROOT/unpacked/Strings/UI.json"
```

Команда проверена на `UI.xnb`: ожидаемый итог xnbcli — `Success 1`, `Fail 0`, а результат появляется в `unpacked/Strings/UI.json`. В среде без интернета xnbcli может сначала вывести ошибку проверки собственного обновления; она не мешает локальной распаковке, если итоговый счётчик успешен.

Это пример для чтения одного файла, а не команда для изменения игры. Для полного набора повторить копирование только нужных базовых XNB. Не запускать `pack` и не записывать ничего обратно в `Contents/Resources/Content`.

Для каждой строки зафиксировать:

- точный Content Patcher `Target`, например `Strings/UI` или `Characters/Dialogue/Abigail`;
- точный ключ записи;
- полный английский текст и контекст использования;
- все плейсхолдеры, управляющие маркеры и варианты текста.

Имена targets и ключей регистрозависимы. В `Target` расширение `.xnb` не пишется.

## 4. Формат патча

Минимальный файл перевода выглядит так:

```json
{
  "Changes": [
    {
      "Action": "EditData",
      "Target": "Strings/UI",
      "When": {
        "Language": "pl-vnrevival"
      },
      "Entries": {
        "AcceptQuest": "Przyjmij zadanie"
      }
    }
  ]
}
```

Правила:

- поле `Format` находится только в корневом `content.json`; во вторичных файлах, подключаемых через `Include`, оно запрещено Content Patcher;
- переводится только значение внутри `Entries`;
- ключ `AcceptQuest`, `Target`, `Action` и код языка не переводятся;
- каждый `EditData` должен иметь условие с точным `languageCode` из `PackageConfig.json`, иначе текст затронет другие языки;
- один файл может содержать несколько `Changes`;
- большие разделы лучше раскладывать по понятным файлам или папкам: `strings-ui.json`, `objects.json`, `locations.json`, `dialogue/abigail.json`, `events/town.json`;
- каждый новый файл нужно явно подключить отдельным `Include` в корневом `content.json`.

Пример подключения:

```json
{
  "Action": "Include",
  "FromFile": "assets/translations/dialogue/abigail.json"
}
```

В рамках уже опубликованного пакета не переименовывать его `UniqueID` и `languageCode`: установщик проверяет их, а сохранённый выбор языка зависит от кода. Для нового языка создать новые стабильные значения и затем не менять их между обновлениями.

## 5. Что нельзя повреждать при переводе

Следующие элементы сохраняются посимвольно и в том же количестве, если изменение не было отдельно проверено по синтаксису игры:

- форматные аргументы `{0}`, `{1}`, `{2}`;
- имя игрока `@` и другие подстановки игры;
- маркеры диалога и эмоций: `#$e#`, `#$b#`, `$h`, `$s`, `$a`, `$u`, `$8` и подобные;
- Content Patcher-токены `{{...}}`;
- временные/форматные токены `[HOURS_24_00]`, `[MINUTES]` и подобные;
- `\n`, кавычки, обратные слеши и необходимое JSON-экранирование;
- числовые ID, item queries, условия, имена NPC и технические команды;
- в событиях — команды, разделители `/`, координаты, направления, паузы, имена музыки/звуков и структура ветвлений.

Для согласования польского текста с полом персонажа игрока использовать установленный игрой шаблон `${męski wariant^żeński wariant}$`, но только там, где грамматическая форма действительно зависит от пола. Не заменять его двумя обычными фразами и не придумывать другой синтаксис.

В event-строках переводить только реплики внутри соответствующих `speak`, `message`, `question`, `textAboveHead` и других текстовых команд. Не переводить весь event script механической заменой.

## 6. Редакторские правила

- Перевод выполнять самостоятельно с английского оригинала. Не использовать API машинного перевода и не копировать официальную локализацию другого языка.
- Перед переводом прочитать соседние строки, сцену или описание механики. Короткая строка интерфейса без контекста часто многозначна.
- Сохранять характер персонажей, степень формальности, шутки и намеренную странность оригинала. Не унифицировать голоса NPC.
- Писать естественно по-польски, а не калькировать английский порядок слов.
- Соблюдать польскую орфографию, диакритику, кавычки, тире, прописные буквы и написание имён последовательно. Конкретное решение глоссария важнее личного предпочтения переводчика.
- Не добавлять смысл, подсказки или цензуру, которых нет в оригинале.
- Ограничения интерфейса учитывать: короткие кнопки и подписи не раздувать без необходимости.
- Не считать строку готовой, если неясно, кто говорит, к чему относится плейсхолдер или где она отображается.

## 7. Рекомендуемый порядок полного перевода

Работать небольшими проверяемыми пакетами, а не одним гигантским JSON:

1. Интерфейс, меню, системные сообщения и обучение.
2. Имена NPC, предметов, инструментов, построек, локаций и механик — сначала сверить весь пакет с глоссарием.
3. Описания предметов, рецепты, задания, почта, телевидение и заметки.
4. Повседневные диалоги персонажей, по одному персонажу за пакет.
5. События, фестивали и разветвлённые сцены — последними, поскольку там особенно легко сломать команды.

После каждого пакета записать, какие `Target` и ключи покрыты. Не заявлять процент готовности по количеству файлов: считать уникальные переведённые записи относительно извлечённого английского набора поддерживаемой версии.

## 8. Проверка изменений

Из корня проекта:

```sh
find Sources/StardewTranslationInstaller/Resources/ModPayload -name '*.json' -type f -print0 | xargs -0 -n1 jq empty
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
CLANG_MODULE_CACHE_PATH=/private/tmp/stardew-installer-swift-cache \
swift test --disable-sandbox
./Scripts/release-audit.sh
```

Дополнительно сравнить оригинал и перевод:

- одинаковы ли наборы ключей для выбранного `Target`;
- не потеряны ли `{0}` и другие плейсхолдеры;
- сбалансированы ли управляющие маркеры и кавычки;
- все ли новые JSON подключены в `content.json`;
- нет ли терминов языка сборки, противоречащих его слою глоссария.

Тесты не изменяют настоящую игру. Готовое приложение, напротив, начинает установку автоматически сразу после открытия. Не запускать его ради поверхностной проверки интерфейса без явного намерения установить текущую сборку.

## 9. Критерий готовности пакета

Пакет перевода готов, когда английский источник и контекст проверены, термины сверены со слоем `siteLocale` единого глоссария, текст отредактирован вручную, технические маркеры сохранены, JSON валиден, файл подключён в `content.json`, тесты проходят, а сомнительные строки явно вынесены на ревью вместо догадки.

Техническое устройство польского пакета, точные размеры графических атласов, расширение XNB-шрифтов, обязательные инварианты Content Patcher, воспроизводимая сборка и проверка через журнал SMAPI описаны в [`POLISH_IMPLEMENTATION_RUNBOOK.md`](POLISH_IMPLEMENTATION_RUNBOOK.md). Этот документ обязателен перед изменением кнопки языка, титульного интерфейса, шрифтов, структуры `Include` или процесса упаковки.

Итоговые редакторские выводы по узбекскому пакету, его графические эталоны, полный gate и исправление прямого переключения между VN-языками описаны в [`UZBEK_IMPLEMENTATION_RUNBOOK.md`](UZBEK_IMPLEMENTATION_RUNBOOK.md). Этот документ обязателен перед изменением узбекского текста или assets и общего `VNRevival.LanguageSwitcher`.
