# Узбекский пакет: редакторский и технический runbook

> Архивный документ. Локаль `uz` исключена из канонического каталога VN Revival
> 5 сентября 2026 года и больше не входит в установщик. Описанные ниже пути и
> проверки сохраняются только как историческая техническая справка.

Этот документ фиксирует выводы финализации узбекского перевода VN Revival для Stardew Valley 1.6.15. История отдельных партий остаётся в [`UZBEK_TRANSLATION_PROGRESS.md`](UZBEK_TRANSLATION_PROGRESS.md), а универсальные правила — в [`TRANSLATION_GUIDE.md`](TRANSLATION_GUIDE.md).

## 1. Идентичность и источник истины

- SiteForMods locale: `uz`.
- Stardew Valley language code: `uz-vnrevival`.
- Content Patcher UniqueID: `VNRevival.StardewValleyUzbek`.
- Каталог перевода: `assets/translations/uzbek/`.
- Английский оригинал для финализации: Stardew Valley 1.6.15.
- Каноническая терминология: `Documentation/glossary/glossary.uz.json` и [проект узбекского перевода VN Revival](https://vnrevival.fun/ru/games/stardew-valley/projects/uz).

Переводить нужно только с английского оригинала. Другие языковые пакеты допустимы как техническая карта `Target`/ключей и образец Content Patcher, но не как источник формулировок.

На момент финализации пакет содержит 463 подключённых JSON-файла и покрывает 14 720 уникальных пар `(Target, key)`. Из них 14 642 записи напрямую сопоставлены с извлечённым английским источником; 78 записей `Strings/credits` не присутствуют в том снимке и требуют отдельной ручной проверки, а не догадки по похожим ключам.

## 2. Что оказалось важным для узбекского текста

- Глоссарий применяется по стабильному ID, а не поиском похожего слова. Финальный слой `uz` содержит 673 из 673 записей и должен совпадать с каноническим источником целиком.
- Форму термина можно согласовать с падежом, числом и предложением, но терминологическую основу менять нельзя.
- Узбекские `o‘` и `g‘`, кавычки и английские апострофы внутри исходных имён нельзя нормализовать глобальной заменой. Сначала нужно установить роль символа и свериться с канонической записью.
- Короткие подписи проверяются в реальном интерфейсе. Формально правильная строка может не помещаться; например, для опции пропуска вступления понадобилась компактная форма `Kirishni o‘tkazib yuborish`.
- Реплики NPC нельзя выравнивать под единый нейтральный стиль: сохраняются голос персонажа, степень формальности, шутка и намеренная неловкость оригинала.
- Неясную строку нужно искать в соседних ключах, сцене и английском asset. Отсутствие контекста не даёт права угадывать.

## 3. Технический контракт строк

До и после каждой правки должны совпадать ключи и мультимножества технических элементов:

- `{0}`, `{1}`, `{2}` и другие форматные аргументы;
- `@`, `%farm` и игровые подстановки;
- `$h`, `$s`, `$a`, `$u`, `$q`, `$r`, `$p`, числовые `$`-маркеры;
- `#$b#`, `#$e#`, обратные слеши и значимые окончания строк;
- гендерные шаблоны `${...^...}$`;
- Content Patcher-токены `{{...}}`;
- технические ID, item queries и условия.

В event-строках переводится только видимый текст команд `speak`, `message`, `question`, `quickQuestion`, `textAboveHead` и аналогичных. Разделители `/`, порядок команд, ветки `fork`, координаты, тайминги, музыка, звуки, анимации и финальные команды сцены сохраняются. При финализации отдельно были структурно сопоставлены 308 event scripts.

Корневой `content.json` — единственное место для `Format`. Каждый вторичный файл должен иметь непустой `Changes`, не иметь `Format`, использовать точное условие `Language: uz-vnrevival` и подключаться через `Include` ровно один раз.

## 4. Графические ресурсы и визуальная проверка

Узбекский пакет использует латинский игровой шрифт (`UseLatinFont: true`), но язык нельзя считать готовым без проверки всех нестандартных символов и реального переноса текста.

Обязательные ресурсы:

- `assets/button-uzbek.png` — атлас кнопки языка 174×78, два состояния по вертикали, надпись `O’ZBEK VN`; он должен совпадать по деревянной рамке, кремовой заливке, красному пиксельному шрифту, масштабу и выравниванию с соседними VN-кнопками;
- `assets/title/TitleButtons-uzbek.png` — атлас главного меню 400×655 с надписями `YANGI O‘YIN`, `YUKLASH`, `HAMKORLIK`, `CHIQISH`, `ORQAGA`, `YARATUVCHI`.

Размер файла сам по себе недостаточен. Нужен снимок настоящего меню рядом с другими VN-языками: проверяются отступы, базовая линия, оба состояния кнопки, обрезка и визуальное соответствие стилю Stardew Valley.

Зафиксированные SHA-256 финальных ресурсов:

- `button-uzbek.png`: `73fa75985fbbe0296ee43d6f7947e538d5895a874bb63886d04349ed137be2cf`;
- `TitleButtons-uzbek.png`: `dd7969a1146d8eb96aeef751e7e634f07cef3b5490529fe3803f9d97430e3980`.

Если графика меняется намеренно, нужно одновременно обновить тестовый эталон, пересобрать приложение и повторить живую визуальную проверку.

## 5. Почему прямое переключение VN → VN требовало SMAPI-мода

У Stardew Valley 1.6.15 есть отдельный дефект при переходе между двумя дополнительными языками. `LocalizedContentManager.SetModLanguage` сначала сохраняет новый `ModLanguage`, затем снова устанавливает enum языка в `mod`. Если текущий язык уже `mod`, setter досрочно завершается: событие смены языка и инвалидация локализованных assets не происходят. Поэтому VN → встроенный язык работает, а VN → другой VN внешне ничего не меняет.

Общий мод `VNRevival.LanguageSwitcher` исправляет только этот переход:

- исходник: `Tools/VNRevivalLanguageSwitcher/ModEntry.cs`;
- сборка: `Scripts/build-language-switcher.sh`;
- устанавливаемый payload: `Sources/StardewTranslationInstaller/Resources/LanguageSwitcherPayload/`;
- папка в игре: `[SMAPI] VN Revival Language Switcher`.

Harmony-prefix срабатывает только когда текущий язык — `mod`, а выбран другой объект `ModLanguage`. Он временно сбрасывает закрытое поле `_currentLangCode` в `en`; затем оригинальный метод игры выполняет один обычный переход `en → mod` уже с новым языком. Не нужно вручную вызывать события или очищать Content Patcher cache.

Установщик обязан ставить этот общий payload до языкового Content Patcher-пакета. Нельзя копировать исправление в каждый язык под новым UniqueID: несколько одинаковых Harmony-патчей создадут лишний риск.

После изменения переключателя проверить по SMAPI-журналу прямую цепочку как минимум из трёх VN-языков. Успешная проверка должна показать смену locale и повторную загрузку локализованных assets, в том числе `Minigames/TitleButtons.<locale>`.

## 6. Финальный редакторский gate

Один чистый автоматический прогон не является завершением. После любой правки сбросить счётчик и выполнить две последовательные полные проверки всех записей без новых изменений между ними.

Для каждого финального прохода должны быть нулевыми:

```text
errors
warnings
localGlossaryDiffs
staleTermHits
englishPhrases
englishBigrams
englishWords
actionableUntranslatedText
actionableEventText
actionableGlossaryExact
actionablePreserved
actionableSourceMissing
```

Отдельно проверить:

1. Все JSON разбираются.
2. Набор `Include` точно равен набору 463 переводных файлов.
3. У source-backed записей совпадают ключи, плейсхолдеры, управляющие маркеры и переносы.
4. Все 308 event scripts сохраняют техническую структуру.
5. Локальный глоссарий содержит те же 673 ID и значения, что канонический слой `uz`.
6. `swift test --disable-sandbox` проходит с toolchain полного Xcode.
7. `./Scripts/build-app.sh` завершается успешно, а `codesign --verify --deep --strict` принимает приложение.
8. В собранном приложении `ModPayload` и `LanguageSwitcherPayload` побайтово совпадают с исходными каталогами.
9. Живая проверка покрывает узбекский текст, кнопку языка, главное меню и прямые переходы VN → VN.

Обычный `swift test` может выбрать Command Line Tools без модуля `Testing`. Для воспроизводимой проверки использовать:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
CLANG_MODULE_CACHE_PATH=/private/tmp/stardew-installer-swift-cache \
swift test --disable-sandbox
```

## 7. Режим сопровождения

Текущий пакет находится в maintenance mode. Новая работа возникает при обновлении Stardew Valley, изменении канонического глоссария или обнаружении проблемы в игре. В таком случае:

1. заново извлечь английские base assets без locale suffix;
2. пересчитать полный набор `(Target, key)`, не полагаясь на старое число 14 720;
3. перевести только новые или изменённые записи с английского;
4. применить актуальный слой `uz` по стабильным glossary ID;
5. повторить полный двухпроходный gate и живую проверку.
